
Explicit one-shot native observation (separate read-only connection):
fr robot observe NODE_ID --native-once --experimental-native --display HANDLE|only
    [--by-name] [--worker /absolute/fr-media-worker] [--x-display :0]
    [--trust-roots /absolute/ca-roots.pem] [--socket /absolute/tailscaled.sock]
    [--port 8443] [--ipv6] [--fit WIDTHxHEIGHT]
    [--evidence-level decoded|submitted_to_compositor] [--screenshot /path/screen.png] [--json]
The --native-once prefix immediately follows NODE_ID. This explicitly opens ONE
new observation, subject to normal tailnet/TLS admission and host approval. It
opens the native viewer, records its first decoder completion even on an idle
screen, runs InspectionComplete closure, and waits for local native cleanup.
It never requests input, clipboard, files or audio, and never reconnects.
Output is historical evidence, never a current input precondition. An explicit
--screenshot writes the first presented viewport as PNG after native cleanup,
including fitted letterboxing and any remote cursor overlay, not the native OS
pointer. The destination must not exist; output is at most 32 MiB of raw pixels
plus bounded PNG framing. Pixel dimensions describe the viewport separately
from the selected host display. Capture times and source freshness stay unknown.
Compositor submission is not physical visibility. This requires a local X11
display, not headless capture. No screenshot is retained unless requested.

Reusable foreground view-only observation publisher:
fr robot session open NODE_ID --foreground --role view --publish-observations
    --experimental-native --display HANDLE|only [read-only options above]
fr robot session status NODE_ID --json
fr robot observe NODE_ID --connection-id HEX32 [--max-receipt-age-ms 1..60000]
    [--screenshot /path/new-screen.png] [--evidence-level decoded|submitted_to_compositor] [--json]
The opt-in owner stays foreground with one attempt; status supplies its public
comparison ID. Reads authenticate that existing local owner and never dial,
capture, reconnect or grant input. Receipt age is local metadata age, NOT host
source freshness. With --screenshot, the original worker copies one retained
presented viewport; this does not recapture or decode a new frame. The same
32 MiB raw-pixel, PNG, cursor and new-file rules above apply. The owner stays
connected. Only one export is in flight, including a slow reader; no recording
or automatic pixel publication is enabled by opening an owner.

A foreground control owner explicitly opened with --accept-input also accepts
--connection-id ID --screenshot PATH. Its result includes control_authority with
the ORIGINAL lease comparison handle, observation_id, next_request_id, all view
generations, frame and bounded source age. Use those same handles for input;
do not read --status between screenshot and action, which creates a new pin.
IPC and PNG-writing time age the original observation. At 1000 ms the returned
input readiness and handles are cleared; the image remains historical. Input
still rechecks its original age and authority on submission. Screenshots never
request or renew a control lease, perform an action or retry a stale picture.
Concurrent status/input, recovery, stop and expiry can refuse an export; no
replacement frame or precondition is silently selected. Ordinary owners refuse.
If --max-receipt-age-ms expires while writing, the error explicitly reports that
the new file was written but provides no current input precondition.
Close with fr disconnect or robot session close --connection-id HEX32; cleanup
remains mandatory. Metadata-only reads retain their existing read-only scope.
Without --native-once or --connection-id, robot observe remains unavailable.
