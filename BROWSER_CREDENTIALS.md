# Browser credential generation and consumption

The browser policy engine generates each 256-bit nonce and attachment ticket
with `getrandom::fill` from the operating system. Time, peer address, role,
session identifiers and counters are binding metadata, not entropy. A failed
entropy read returns a typed refusal; there is no deterministic fallback.

Each manager lazily obtains an independent 256-bit OS-random HMAC key. It retains
only domain-separated HMAC-SHA256 tags and binding metadata, not bearer bytes.
The existing pinned TLS/runtime graph already contains ring 0.17.14 and subtle
2.6.1; frd names those same versions directly rather than implementing another
cryptographic primitive. No new package or runtime is added to Cargo.lock.
Raw credentials are returned only to the issuing caller for delivery over the
already origin-checked channel. Binding record structs no longer contain their
old plaintext nonce/ticket fields. Manager Debug output reports counts only.

Lookup scans the entire bounded store using subtle's fixed-size constant-time
comparison and conditional selection. It has no raw-secret HashMap probe,
prefix comparison, or early exit on a match. This does not make the entire HTTP
exchange constant-time: store occupancy, binding decisions and final outcomes
remain observable. The tests are functional regressions, not deployed hardware
side-channel qualification.

A successful consume remains atomic and one-use under the existing mutable
owner/mutex. Wrong peer, session or role does not burn a legitimate credential.
Expiry is exclusive at the original deadline, never renewed by an attempt;
pre-issuance timestamps and overflowing validity intervals are refused. Global
and per-peer count bounds remain unchanged. At most eight colliding candidates
are tried, without overwriting the previous credential or charging a failed
issuance as a new record. OS entropy, the host clock, and the owning process
remain trusted; this is not a compromise-resistant vault or a zeroization claim.

Focused verification commands on a provisioned builder:

```sh
cargo test -p frd --test browser_credentials
cargo test -p frd --test browser_security_attack_tests
cargo test -p frd --lib broker::browser_security::
```

The delivery's four public-manager regressions fail against the original
production code and pass with this change. Private tests cover entropy failures,
bounded collisions, keyed storage, binding mismatch/replay, time boundaries and
100,000 unique tokens generated by the actual OS-backed public APIs. Existing
browser attack tests are preserved. This fixes fr-rc-sec-csprng-nonces-go6's
implementation; it does not wire or qualify a browser ingress server, replace
Tailscale/node admission or Origin checks, or grant observation/input authority.
